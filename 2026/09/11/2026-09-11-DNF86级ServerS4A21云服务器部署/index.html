DNF 86级端 ServerS4A21 云服务器部署全流程：.NET 10 服务端从零编译到联机

发表于2026-09-11|更新于2026-09-11|技术
|浏览量:

本文是个人技术学习记录：基于开源项目 ServerS4A21（.NET 10 从零重写的 DNF 服务端模拟器），在 Ubuntu 24.04 云服务器上把 86 级服务端跑起来并与朋友联机。仅供学习研究网络游戏服务端架构，绝不开服、不收费、不传播，请务必遵守。

一、写在前面

⚠️ 声明：DNF 相关版权归 Nexon 等权利方所有，本文搭建的服务端源自公开的第三方开源学习项目，项目本身定位就是”研究网络游戏服务端架构与协议”。写作目的仅为个人技术学习，**红线是”只学习自用、不开服、不收费、不传播”**。

之前写过一篇 DNF 85级端 Docker 私服搭建，那套是”镜像打包好、一键起容器”的路子。这次折腾的 ServerS4A21 完全是另一条技术路线：

1.1 为什么单独写 86 级这一版

  • 技术栈新：不是老一套 C++ + MySQL + 专用进程管理，而是 .NET 10 从零重写，跨平台（Windows / Linux / macOS 都能编译）；
  • 数据库换成了 SQLite：单文件 inventory.db，不用装 MySQL、不用导 SQL，首次启动自动建库；
  • 账号自动创建：客户端首次登录时自动建号，省掉手动写表；
  • 可以和云服务器结合：裸装编译的方式更适合丢到云上，和朋友联网。

1.2 需要有的心理准备

项目作者自己就明说了：仍处于研究和开源完善阶段，还存在非常多 BUG。组队、副本等玩法成熟度有限，别指望它像正式服一样稳。请以”研究服务端架构”的心态对待，而不是”找个服玩”。

二、架构总览

  • 服务端：跑在云服务器（Ubuntu）上，从源码编译；
  • 客户端：跑在玩家 Windows 上，连接服务端公网 IP；
  • 关键规则：服务端与所有客户端的 Script.pvf 必须是同一份。

和 Docker 方案最大的区别是：这里没有容器兜底，服务端直接跑在宿主机上，所以端口放行、进程守护、内存都得自己管。

三、准备工作

3.1 需要的东西

3.2 云服务器选型参考

项 建议
系统 Ubuntu 24.04 LTS
配置 4核4G 起（服务端 + GM 工具约吃 2.5~3G，建议 8G 或加 swap）
磁盘 40G 起
位置 就近（腾讯云 / 阿里云轻量即可）

💡 内存是这套方案的第一个坎：服务端本身约 800MB，GM 工具首次建索引能到 1.4GB，4G 机器不加 swap 很容易被 OOM 杀进程。

10.5 GM 工具能做什么

  • 发物品：默认走游戏内邮件，在线角色可安全收取，一封最多 10 件装备；
  • 改等级：按经验阈值表写入并重算属性；
  • 转职/觉醒、SP/TP、点券货币、背包、任务、称号等。

💡 它的设计理念是「数据变更走服务端业务代码」，避免直接手改数据库导致数据不自洽——所以别自己拿 sqlite 客户端乱改表。

十二、端口速查表（安全组 / ufw 用）

端口 用途 公网建议
22/tcp SSH 开，来源限定自己 IP
7001/tcp Channel 频道 开
10001-10201/tcp Game 游戏端口 开（整段放行）
5051/tcp GM 工具 默认不开，走 SSH 隧道

十三、排错速查表

症状 原因 / 处理
启动报 schema v28 > v26 git pull 后没重新编译 → dotnet build 再重启
客户端连不上 安全组端口没放行（7001 + 10001-10201）；或 PVF 版本不一致
组队提示防火墙 游戏端口没全放行，确认放的是 10001-10201 整段
GM 工具报 no such table: character_items 用错了旧版 86JPGMTool → 换成 S4A21GmTool
服务端进程莫名消失 内存不足被 OOM → 加 swap 或升内存
找不到 .NET 运行时 用了非 self-contained 发布 → 装 ASP.NET 运行时，或加 --self-contained true
dotnet 命令不存在 PATH 没生效 → source ~/.bashrc

十四、小结

这套方案的链路其实很清爽，三件事串起来：

  1. 服务端：装 SDK → git clone → dotnet build → 放 Script.pvf → nohup 起；
  2. 网络：安全组 + ufw 放行 7001 和 10001-10201；
  3. 客户端：bat 参数里填对 IP + m_id + 密钥，PVF 与服务端保持一致。

只要记住两条铁律——改代码必重新编译、PVF 全员同源——大部分坑都能绕开。

跑通之后可以延伸学习的方向：

  1. 读源码里 Server/ 的分层结构，理解 Channel 与 Game 端口分离的设计；
  2. 用 SQLite 客户端打开 inventory.db，看角色/物品表结构（只读，别改）；
  3. 对比 Docker 那套 85 级端，感受”容器化部署”和”源码裸装编译”两种形态的差别。
