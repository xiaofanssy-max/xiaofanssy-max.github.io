DNF 85级端 Docker 私服搭建全流程：从虚拟机到局域网跑通

发表于2026-09-08|更新于2026-09-08|技术
|浏览量:

本文是个人技术学习记录：基于 GitHub 开源项目 llnut/dnf（清风1031 适配版）的 Docker 镜像，在虚拟机里从零搭建 DNF 85 级服务端并让客户端内网跑通。仅供学习研究游戏服务端架构，绝不开服、不收费、不传播，请务必遵守。

一、写在前面

⚠️ 声明：DNF 是腾讯代理运营的商业游戏，本文搭建的私服端源自公开的第三方开源学习项目。写作目的仅为个人技术学习与怀旧折腾，**红线是”只学习自用、不开服、不收费、不传播”**。请勿将相关资源对外提供或用于商业用途。

这一篇主要记录我这次折腾的完整过程：从建虚拟机、装环境，到最终客户端登录建号进图，以及中间踩过的各种坑。

1.1 为什么选 Docker 方式

老版本 DNF 服务端依赖一堆特定版本的环境（旧内核、老 MySQL、专用进程管理），直接裸装很容易翻车。Docker 镜像把游戏服务 + MySQL + 进程管理全部打包好，首次启动还会自动初始化数据库，不需要手动导 SQL，部署门槛大幅降低。

1.2 为什么用 llnut 清风镜像

我这次用的是开源项目 llnut/dnf（清风 1031 适配版）：

  • 网关换成新版 HTTP 网关，登录服务走 5505 端口，客户端登录器用 AES 密钥通信，比老式 TCP 网关更好配置；
  • 必须搭配其专用清风客户端使用，整套同源最稳；
  • 镜像提供 debian13 / alma9 / ubuntu26 / centos7 四种基础镜像，内容一致，CentOS 7 宿主上选 centos7 变体最稳。

💡 老式网关端常出现”接收频道信息失败 / 频道数恒为 0”这类兼容问题，往往不是配置错，而是网关协议和客户端版本不匹配。llnut 明确要求使用配套清风客户端，不要混用旧客户端。

二、整体架构先看懂

核心要点：

  • 一套镜像 = 游戏服务 + MySQL 全在内，首次启动自动初始化，数据通过 -v 挂载到宿主机 /data 持久化；
  • PUBLIC_IP 填什么：内网测试填虚拟机局域网 IP；上云填公网 IP，其余命令完全一样；
  • 客户端登录需要两个关键信息：服务器地址（http://IP:5505）+ AES 密钥，两者必须与服务端一致。

三、阶段一：准备虚拟机与系统

3.1 创建虚拟机（VMware / VirtualBox）

  • 操作系统选 Linux / CentOS 7 64位（Ubuntu 22.04/24.04 也行，命令基本一致）
  • 内存 8GB（不足 8G 必须配 swap，见阶段三）
  • CPU 4核，磁盘 80GB+
  • 网络选 桥接模式（bridged）——关键，NAT 会导致局域网其他电脑连不上

3.2 安装系统并打快照

  1. 安装 CentOS-7.6-x86_64，软件选择”最小安装”，设好 root 密码；
  2. 重启后立刻拍快照（VMware：虚拟机 → 快照 → 拍摄快照），后面翻车可以随时回滚；

常用小技巧：

  • 若灰频道/进不去：确认 Linux 防火墙已关闭、PUBLIC_IP 填对，部分补丁仍走域名 start.dnf.tw，可在 C:\Windows\System32\drivers\etc\hosts 加一行 PUBLIC_IP start.dnf.tw；
  • 建角色键盘无法输入时，Win10 换系统自带英文输入法。

九、局域网联机与重启恢复

  • 自己这台：登录 → 选频道（siroco11/52）→ 建角色 → 进图打怪 ✅
  • 局域网第二台：同样装客户端 + 配置，或直接复制已配好的客户端文件夹，登录进图 ✅
  • 重启恢复：docker restart dnf，等 1~2 分钟日志重新出就绪标志，客户端重连 ✅

进程被系统杀掉是常态，镜像已带 --restart=always，必要时手动 docker restart dnf 即可恢复。

十一、端口速查表（防火墙 / 云安全组用）

端口 用途 公网建议
3000/tcp MySQL 不开
5505/tcp HTTP 网关 开
7001 tcp+udp 游戏 开

十二、排错速查表

症状 处理
登录器报”网络错误” 服务器地址/AES 密钥不对；5505 没放行；服务端网关没起来（docker exec dnf tail -f /data/log/llnut_gate/current）
接收频道信息失败 确认用的是清风专用客户端（不是旧客户端）
灰频道 / 进不去频道 防火墙/端口；hosts 缺 start.dnf.tw；PUBLIC_IP 填错
AES 报”must be exactly 64 hex” 密钥不是 64 位十六进制，重新 openssl rand -hex 32 并两边同步
服务端反复重启 / UDP socket 38 仅 Docker ≥ 29 需要 seccomp 配置，老版本不需要
建角色键盘无法输入 Win10 用系统自带英文输入法

十三、小结

从建虚拟机到客户端进图，核心就三件事：服务端（Docker 容器）→ 网络（端口 + IP）→ 客户端（地址 + AES 密钥）。只要 PUBLIC_IP、端口、密钥三者一致，基本就能跑通。

跑通之后的延伸学习方向：

  1. 读项目 doc/ArchitectureDiagram.md，理解登录 / 网关 / 频道分层；
  2. 进容器看目录结构，docker exec -it dnf bash；
  3. 连 MySQL 看 taiwan 库的表，理解角色、商城数据结构；
  4. 想玩其他等级版本：研究 PVF 替换与等级补丁。
